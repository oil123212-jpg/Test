# 모모 웹 플레이그라운드

브라우저 중심으로 전환한 Phase 0입니다. 대시보드, 오디오 테스트, 개인정보 보호 안내, 준비 체크리스트를 제공합니다. 화면의 캐릭터는 안내용 일러스트이며 실제 AI 응답이나 아동 동의 검증을 수행하지 않습니다.

## 실행

Node.js **24 이상** 및 npm이 필요합니다. Windows PowerShell, macOS, Linux에서 저장소의 `web/` 디렉터리로 이동합니다.

```bash
npm ci
npm run dev
```

기본 개발 포트는 5173이며 터미널에서 안내하는 서버를 브라우저로 엽니다. 마이크는 HTTPS 또는 브라우저가 신뢰하는 로컬 개발 주소에서만 사용 가능합니다. 일반 HTTP의 원격/LAN 주소에서는 마이크 권한이 제공되지 않을 수 있습니다. 데모 음원은 마이크 권한 없이 사용할 수 있습니다.

Python, PortAudio, Raspberry Pi, API 키는 필요하지 않습니다. 실제 제공자/백엔드로 보내는 요청도 없습니다.

## 사용 순서

1. **데모로 먼저 만나보기**: 브라우저 안에서 5초 합성 음원을 만듭니다. 실제 마이크 수집이나 AI 생성 음성이 아닙니다.
2. **내 마이크 → 권한 확인**: 명시적으로 권한을 요청하고 장치 목록을 갱신합니다. 이 단계는 녹음하지 않으며 확인 후 마이크 트랙을 닫습니다.
3. **5초 녹음하기**: 선택한 마이크를 최대 5초 동안 수집하고 파형·peak·RMS·클리핑을 표시합니다. 녹음이 끝나면 마이크를 닫고 24kHz 모노 PCM16으로 변환합니다.
4. **다시 듣기**: 사용자가 눌러야 재생합니다. 자동 재생/실시간 마이크 루프백은 없습니다.
5. **중단/지우기**: 진행 중 작업을 취소하거나 임시 PCM 버퍼를 0으로 덮습니다. 개인정보 화면의 세션 전체 지우기는 장치 선택·음량·체크 상태도 초기화합니다.
6. **스피커 테스트/설정**: 낮은 볼륨의 1초 사인파를 재생합니다. 출력 선택을 지원하지 않는 브라우저에서는 OS 기본 출력을 사용합니다.

스피커 신호의 기본 진폭은 10%, 최대 20%입니다. 실제 음압 제한이 아니므로 기기 볼륨을 낮춰 성인이 먼저 확인하세요. 체크리스트의 수동 표시는 개인정보 동의나 실제 검증 완료를 대신하지 않습니다.

## 개인정보와 브라우저 제약

- 음성/전사문을 파일·서버·localStorage·sessionStorage·IndexedDB에 저장하지 않습니다. 녹음 데이터는 현재 탭 메모리에서만 처리합니다.
- 실제 AI 연결/음성 인식/외부 음성 업로드/분석·광고·외부 폰트 로딩을 하지 않습니다. 정적 파일 로딩과 개발 서버 HMR 통신은 음성 전송이 아닙니다.
- 호스팅 서버는 정적 파일 요청의 IP/접속 정보를 별도 로그로 남길 수 있습니다. 실제 공개 배포 시 호스팅 로그 정책도 확인해야 합니다.
- 마이크 접근 허용은 브라우저 장치 권한입니다. 법정대리인 확인/개인정보 처리 동의로 간주하지 않습니다.
- 탭이 숨겨지거나 페이지를 떠나면 음성 세션을 정리합니다. 모바일 앱 전환/화면 잠금에도 녹음이 중단될 수 있습니다. 새로고침 후 복구 기능은 의도적으로 없습니다.
- 앱이 소유한 버퍼를 지워도 OS/브라우저 내부 복사본이나 swap의 완전한 물리 삭제까지 보장하지 않습니다.
- AudioWorklet·Web Audio가 있는 최신 브라우저가 필요합니다. 실제 Safari/iOS, Firefox 및 실물 모바일 마이크는 추가 검증 대상입니다. 출력 장치 선택은 기능 탐지 후 지원할 때만 활성화합니다.
- 브라우저 보안상 하드웨어 장치 목록은 권한 확인 전 제한될 수 있습니다. 장치 이름/ID를 로그나 브라우저 저장소로 남기지 않습니다.

## 구조

- `index.html`: 한국어 반응형 화면과 접근 가능한 기본 컨트롤
- `src/main.ts`: 상태, 화면 이동, 명시적 작업, 세션 정리
- `src/audio-engine.ts`: 장치 권한, 수집/리샘플링, 재생과 취소
- `src/audio-utils.ts`: PCM16 변환, 측정, 합성 데모, 버퍼 정리
- `public/capture-worklet.js`: 입력 블록을 모노로 수집; 스피커 출력은 무음
- `public/_headers`: 지원 정적 호스팅용 보안 헤더
- `tests/`: 변환 단위 테스트와 브라우저 기능 테스트

마이크의 실제 샘플레이트로 수집한 뒤 `OfflineAudioContext`로 목표 24kHz로 리샘플링합니다. 녹음 시점 측정값은 리샘플링 전 입력을 기준으로 하며, 재생 시 브라우저가 실제 출력 장치의 주파수에 맞춥니다. 입력/출력은 동시에 실행하지 않습니다. 외부 제공자 스트리밍은 구현하지 않습니다.

## 빌드와 테스트

```bash
npm run build
npx playwright install chromium
npm test
```

Linux CI에서 브라우저 시스템 라이브러리가 없으면 관리 가능한 환경에서 `npx playwright install --with-deps chromium`을 사용하세요. 이 클라우드에서는 설치된 `/usr/bin/chromium`을 사용합니다. 테스트 설정의 가상 미디어 플래그는 **자동화 브라우저에서만** 적용되며 제품 앱은 실제 권한을 요청합니다.

검증: TypeScript 검사/프로덕션 빌드 통과, 2026-10-31 Chromium **30개 테스트 통과**(15개 사례 × 데스크톱/모바일 설정; 이 중 4개씩은 변환/워크릿 단위 테스트). 가상 마이크로 실제 AudioWorklet·Web Audio 경로를 실행했습니다. 5초·120,000 프레임, 권한 확인 후 트랙 해제, 요청 없는 재생 0건, 권한 거부/취소/지연된 권한 응답, 재생 준비 중 취소, 음량 제한, 저장소 미사용, 화면 이동/초기화를 검증했습니다.

모바일 설정은 Chromium 화면/입력 에뮬레이션입니다. 실제 휴대폰/Safari 검증 또는 스피커 청취 완료로 해석하면 안 됩니다. 기존 Python 테스트는 별도이며 웹 검사 결과에 합산하지 않습니다.

## 정적 배포

비공개 저장소를 유지하면서 무료 호스팅을 쓰려면 [Netlify 수동 배포 안내](../docs/free_hosting.md)를 우선 참고하세요. GitHub Pages 활성화나 저장소 공개 전환이 필요하지 않습니다.

```bash
npm run build
npm run preview
```

로컬 프로덕션 확인 기본 포트는 4173입니다. 배포 대상은 `dist/` 안의 파일입니다. Node 서버가 필요한 앱이 아니며 HTTPS 정적 호스팅으로 배포할 수 있습니다. 배포 루트에 `index.html`, `assets/`, `capture-worklet.js`, `favicon.svg`를 배치하세요. 일반 빌드는 사이트 루트를 사용합니다. `npm run build:pages`는 GitHub Pages의 `/Test/` 경로에 맞게 빌드합니다. 아이콘과 마이크 worklet도 해당 경로를 사용합니다. `npm run test:pages`로 같은 경로에서 전체 브라우저 테스트를 실행할 수 있습니다.

권장 검토안은 Netlify 또는 Cloudflare Pages의 정적 호스팅입니다. 저장소 연결 시 root directory는 `web`, build command는 `npm run build`, output directory는 `dist`, Node 버전은 24로 설정합니다. 수동 업로드라면 빌드 결과 전체를 사용하세요. 이 작업에서 외부 호스팅 계정 생성/배포는 수행하지 않았습니다.

`_headers`는 Netlify/Cloudflare Pages 등 지원 호스팅에서 적용합니다. 다른 호스팅은 `vite.config.ts`에 정의한 프로덕션 보안 헤더를 호스팅 설정으로 별도 적용하세요. Vite preview의 헤더가 외부 호스팅에 자동으로 적용되는 것은 아닙니다. HTTPS, microphone 권한, 실제 오디오, MIME 타입, worklet 경로를 배포 후 다시 확인해야 합니다.

향후 실제 AI는 [웹 전환 설계](../docs/web_transition.md)의 서버 인증/중계 구조로 연결합니다. 브라우저에 장기 제공자 API 키를 입력하는 UI나 환경변수는 추가하지 않습니다.

## GitHub의 별도 버전과 Pages

- 기존 기준 버전: `v0.1.0` 태그
- 새 웹 버전: `release/web-v0.2.0` 브랜치 및 `v0.2.0` 태그
- 정적 배포 파일: `gh-pages` 브랜치

소스 커밋을 완료하고 `npm run test:pages`를 실행한 뒤 저장소 루트에서 `python3 scripts/publish_pages.py`를 실행하면 정적 빌드를 gh-pages로 업로드합니다. 원본 소스 브랜치나 기본 Git index를 변경하지 않으며 force push하지 않습니다. 게시되는 `version.json`에는 버전과 소스 커밋이 포함됩니다.

최초 사이트 활성화는 GitHub **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: gh-pages, /(root) → Save**로 설정합니다. 저장소 공개/비공개 상태와 요금제에 따라 Pages 사용 가능 여부도 확인해야 합니다. 설정/실행 완료 전에는 사이트가 실제 서비스 중이라고 간주하지 않습니다.

대안으로 Source를 GitHub Actions로 설정하면 **Deploy Momo to GitHub Pages** 워크플로를 수동 실행할 수 있습니다. 기본 입력은 `v0.2.0`이며 배포할 태그/브랜치를 지정할 수 있습니다. 두 방식을 동시에 사용할 필요는 없습니다. GitHub Pages는 `_headers`를 보안 헤더 설정으로 해석하지 않으므로, 다른 호스팅의 헤더가 자동 적용된다고 가정하지 않습니다. 현재 정적 앱은 API 키와 외부 음성 업로드 기능이 없습니다.
