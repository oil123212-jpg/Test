# 실제 오디오 장치 점검

> 2026-10-31 웹 전환: [최신 설계 및 검토 기준](../../docs/web_transition.md). 아래는 기존 Python/디바이스 기반 기록입니다. 제공자·개인정보 검토는 유지하고, Pi 장치 및 기기 인증 항목은 웹 기준으로 대체합니다.

## 공통

1. 성인 개발자가 USB 마이크/스피커를 연결하고 낮은 하드웨어 볼륨으로 시작합니다.
2. `python main.py --devices`에서 입력/출력 채널과 ID, 기본 샘플레이트를 확인합니다.
3. `.env` 또는 `--input-device`/`--output-device`로 선택합니다. 장치 ID는 재연결/부팅 후 바뀔 수 있으므로 다시 조회합니다.
4. 마이크 단독 테스트에서 RMS/peak/clipping 값을 확인합니다. 클리핑은 입력 이득을 낮춰 해결합니다. 잡음/무음 여부는 수동으로 점검합니다.
5. 스피커 사인파 테스트는 1초입니다. 실제 출력과 안전한 음압은 사람이 확인합니다.
6. 통합 테스트에서는 녹음 후 PLAY를 입력해 재생을 요청합니다. 녹음 중 스피커로 실시간 출력하지 않습니다.
7. 녹음/재생 각각에서 Ctrl+C와 장치 분리 오류를 점검하고 이후 재실행할 수 있는지 확인합니다.

## Windows

64비트 Python 3.11 이상을 권장합니다. sounddevice wheel의 PortAudio를 사용합니다. 마이크 개인정보 권한, 기본 입력/출력, 다른 앱의 독점 점유를 확인하세요. OS 권한을 임의로 우회하지 않습니다.

## Raspberry Pi 5

64비트 Raspberry Pi OS, `python3-venv`, `libportaudio2`가 필요합니다. Pi 5에는 아날로그 3.5mm 오디오 잭이 없으므로 USB/HDMI/오디오 HAT 등 적절한 출력 장치를 준비하세요. 필요할 경우 OS의 ALSA/PipeWire 장치 설정과 사용자 권한을 확인하세요. 실행을 위해 전체 프로그램을 root로 실행하지 않습니다.

24kHz를 지원하지 않으면 앱은 지원되는 기본/48k/44.1k 주파수를 검사하고 필터 기반 리샘플링합니다. 지원되는 주파수가 없거나 버퍼 오버/언더플로가 발생하면 성공으로 처리하지 않습니다. 장치별 실제 지원 및 latency는 하드웨어에서 검증해야 합니다.

## 클라우드

실제 마이크/스피커가 없는 환경에서는 단위 테스트만 유효합니다. PortAudio 설치와 import는 장치 존재를 증명하지 않습니다. 이 환경의 장치 수는 0입니다. 컨테이너의 가짜 ALSA 장치를 실제 하드웨어 검증으로 취급하지 않습니다.
