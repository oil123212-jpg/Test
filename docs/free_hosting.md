# 비공개 저장소를 유지하는 무료 정적 배포

GitHub는 소스와 버전 관리용으로 유지하고, 웹사이트는 Netlify 무료 플랜의 수동 업로드로 배포합니다. GitHub Pages의 비공개 저장소 요금제 제한을 피하기 위해 저장소를 공개로 전환할 필요가 없습니다. 제공자의 무료 플랜 사용 한도는 해당 계정의 현재 플랜을 기준으로 합니다.

## 가장 간단한 방법

1. Netlify 계정을 만들거나 로그인합니다. 이 프로젝트 때문에 유료 플랜을 선택할 필요는 없습니다.
2. 준비된 `momo-web-v0.2.0-netlify.zip`을 내려받아 압축을 풉니다.
3. [Netlify Drop](https://app.netlify.com/drop)에 `index.html`이 바로 들어 있는 **dist 폴더**를 끌어 놓습니다. 소스 저장소나 node_modules를 올리는 것이 아닙니다.
4. 발급된 HTTPS 주소에서 데모, 실제 마이크 권한, 녹음 후 재생, 중단/삭제를 확인합니다.

무료 배포만으로 이번 Phase 0의 정적 사이트를 실행할 수 있으며, 실제 AI 연결이나 API 사용료는 발생시키지 않습니다. 현재 앱에 AI API 호출이 구현되어 있지 않기 때문입니다. 호스팅 한도와 향후 실제 AI 사용료는 별도입니다.

정적 사이트는 방문자가 다운로드해 실행하는 공개 웹 파일입니다. GitHub 저장소를 비공개로 유지해도 웹에 배포한 HTML/JS는 방문자가 볼 수 있으므로 비밀/API 키를 포함하면 안 됩니다. 현재 빌드에는 API 키가 없습니다.

## 직접 다시 빌드할 때

저장소의 web 디렉터리에서 `npm ci`, `npm run build`를 실행하고 만들어진 dist 폴더를 업로드합니다. 이 경로는 사이트 루트용 일반 빌드입니다. GitHub Pages용 `build:pages` 또는 `test:pages` 결과(`/Test/` 경로)를 Netlify에 업로드하면 안 됩니다.

Netlify는 포함된 `_headers` 파일의 보안 헤더를 지원합니다. HTTPS 주소에서 마이크 권한을 사용하세요. 스마트폰/Safari의 실제 동작과 안전한 출력 볼륨은 사람이 확인해야 합니다.

## 자동 배포 상태

이 클라우드에는 Netlify 계정/사이트 인증이 연결되어 있지 않습니다. 배포 파일 준비와 로컬 프로덕션 브라우저 검증만 수행하며, 공개 사이트가 생성됐다고 주장하지 않습니다. 수동 업로드 방식은 클라우드에 토큰을 넣거나 GitHub 저장소 접근을 추가로 허용할 필요가 없습니다.
