# 라이프 가이드 — 부모님용 생활 시간 설정

## 이용 방법

왼쪽 메뉴(모바일은 상단 잎사귀 아이콘)의 **라이프 가이드**에서 부모님이 설정합니다.

1. 체험 로그인 팝업에서 안내에 동의하면 PostgreSQL의 이 브라우저 시간표를 불러옵니다. 밥 먹기, 잠자리 준비, 청소·정리별로 매일 반복할 30분 시간대를 여러 개 선택합니다. 새벽·아침·오후·저녁 묶음을 펼쳐 00:00–24:00 전체를 선택할 수 있습니다.
2. 생활 시간 기준을 확인합니다. 기본은 한국 시간 `Asia/Seoul`이며 기기 시간대와 UTC도 선택할 수 있습니다. 서버의 UTC 시간 대신 선택한 IANA 시간대로 매 응답 직전 판단합니다. 시간대가 지원하는 일광절약시간도 따릅니다.
3. **저장하고 적용**을 누르면 시간표만 DB에 저장합니다. **생활 이야기를 모모에게 연결하기**는 현재 탭의 대화에 적용하며 DB에 저장하지 않습니다. 재로그인하면 꺼진 상태로 시작합니다. 비활성 상태로 시간만 저장할 수도 있습니다.
4. 대시보드에서 기존 로그인 팝업과 별도 음성 전송 안내에 동의한 후 대화를 시작합니다. 설정을 저장하거나 시간이 되었다는 이유만으로 음성 생성이나 마이크 수집을 시작하지 않습니다.
5. 설정 변경은 현재 생성 중인 답변이 아닌 다음 답변부터 적용됩니다. 연결 중 변경도 최종 설정으로 동기화합니다. **저장한 생활 시간 삭제**는 현재 연결에서도 생활 화두 제안을 끕니다. 이미 생성·전달된 응답이나 제공자 기록을 소급 삭제하는 기능은 아닙니다.

## 화두를 제안하는 방식

- 서버가 OpenAI VAD의 `input_audio_buffer.committed`를 받은 뒤 `response.create`를 한 번 보냅니다. `create_response:false`로 자동 응답과 서버 응답이 중복되지 않도록 합니다. 타이머·푸시·예약 작업은 없습니다.
- 현재 30분에 해당하고 아직 이 대화에서 제안하지 않은 항목이 있는 사용자 발화만 후보로 셉니다. 후보 세 번의 묶음마다 무작위 한 위치를 선택하며 묶음 경계에서도 연속 제안을 피합니다. 첫 번째 후보에서 바로 제안할 수도 있습니다.
- 같은 항목·현지 날짜·30분은 **한 연결에서 최대 한 번** 제안합니다. 겹친 항목이 여럿이면 하나만 선택합니다. 설정 수정/끄기 후 다시 켜기로 이 반복 방지 기록을 초기화하지 않습니다. 새 대화를 시작하면 새 기회가 생깁니다.
- 지침은 사용자의 질문에 먼저 답하고 대화 흐름에 어울릴 때만 짧고 부드러운 질문 하나를 연결하도록 합니다. 재촉·명령·죄책감 유도를 금지하고 거절/이미 했다는 말은 존중합니다. 흐름에 어울리지 않으면 생략할 수 있어 **실제 발화 비율을 정확히 1/3로 보장하지 않습니다**. 음성 의미를 별도로 분류하거나 생활 실천 여부를 기록하지 않습니다.
- 일반 응답에는 생활 화두를 자발적으로 꺼내지 말라는 개별 지침을 전달합니다. 사용자가 먼저 생활 주제를 묻는 경우에는 답할 수 있습니다. 전체 생활표를 모델에 상시 넣지 않습니다.
- 응답 도중 새 발화가 들어오면 기존 응답 취소 완료를 기다려 다음 답변을 생성합니다. 중복 committed 이벤트는 무시합니다. 현재 미청취 구간의 `conversation.item.truncate`는 여전히 미구현입니다.

## 저장과 데이터 흐름

- PostgreSQL의 `momo_life_guides` 테이블에 `device_hash`(무작위 브라우저 쿠키의 SHA-256)와 `schedule`(version/timeZone/세 항목의 0–47 슬롯 번호)만 저장합니다. 활성 여부·동의·이름·음성·전사문은 저장하지 않습니다. 로그인만으로 데이터 행을 생성하지 않습니다. 시간표는 직접 삭제할 때까지 남습니다.
- HttpOnly/SameSite=Strict 쿠키로 같은 브라우저를 구분합니다. HTTPS에서는 Secure도 적용합니다. 기기 식별 쿠키는 최대 1년, 임시 로그인은 서버 메모리에서 12시간 유지합니다. 로그아웃/페이지 종료 시 임시 권한을 폐기하고 기기 식별은 남깁니다. 새로고침 후 다시 체험 로그인해야 합니다. 서버 재시작이나 여러 replica 사이에서는 재로그인이 필요할 수 있으므로 현재 테스트 서버는 replica 하나를 사용합니다.
- 실제 계정 로그인·법정대리인 인증·다른 기기에서 같은 계정으로 복구하는 기능은 없습니다. 쿠키를 지우거나 시크릿 모드/다른 브라우저를 쓰면 새 기기로 취급됩니다. 쿠키를 먼저 지우면 이전 시간표에 대한 접근도 잃으므로 필요 시 시간표를 먼저 삭제합니다.
- 예전 localStorage 시간표는 DB에 데이터가 없을 때 미저장 초안으로만 보여 주며 자동 업로드하지 않습니다. 사용자가 저장하면 DB에 옮기고 예전 복사본을 정리합니다. 새 시간표를 브라우저 저장소에 쓰지는 않습니다.
- 활성 설정만 POST 세션 발급 및 허용된 `life_guide.update` WebSocket 메시지로 Railway에 전달합니다. 꺼진 설정의 실제 시간 목록은 보내지 않습니다. Railway는 해당 세션 메모리에서 처리하고, 선택된 화두 응답에서만 현재 생활 항목과 시간대를 OpenAI 지침에 넣습니다.
- 다른 같은 출처 탭에서 삭제/변경하면 BroadcastChannel을 통해 DB 시간표를 다시 조회하고 연결을 꺼 재확인을 받습니다. 저장 실패 시 변경 전 설정을 유지하고 실패를 표시합니다. 삭제 시 DB 접근이 막히면 현재 세션부터 끄고 DB 삭제 미완료를 명확히 안내합니다.
- 서버는 버전·활성 여부·IANA 시간대·세 목록의 정수 범위 및 길이를 검증하고 필요한 값만 재구성합니다. 자유 형식 프롬프트는 허용하지 않습니다. 메시지/HTTP 본문 크기 제한은 그대로 유지하며 라이브 수정은 분당 30회로 제한합니다. 생활 설정이나 전사문을 로그에 출력하지 않습니다.
- 이 페이지는 부모님 대상 UI이며 실제 계정 인증이나 보호자 확인 기능은 아닙니다. 기존 성인용 Realtime 체험 범위를 유지합니다.

## 검증

`cd web`에서 `npm run test:server`, `npm run test:realtime`을 실행합니다. 전자는 시간 경계·자정·시간대·일광절약시간·세 번 중 한 번·반복 억제·스키마·실제 WS 릴레이의 설정 주입/삭제/끼어들기를 확인합니다. 후자는 데스크톱 및 모바일 Chromium에서 시간표 선택/저장/새로고침/삭제, 저장 실패, 탭간 변경, 실시간 설정 전달을 확인합니다. 제공자 응답은 모의 서버를 사용하므로 실제 OpenAI 답변 문장과 iPhone/Safari 음성은 별도 확인 대상입니다.

Railway의 웹 서비스 Variables에 PostgreSQL 서비스의 `DATABASE_URL` 참조를 연결해야 합니다. [DB 설정](railway_deployment.md#postgresql-생활-시간표-저장)을 참고하세요. DB 주소는 서버 프로세스에서만 사용합니다. Docker 빌드/실행 단계에 `pg`, DB API와 공용 `web/shared` 모듈을 포함합니다.
